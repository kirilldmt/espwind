# WIND64 — сборка, установка и разработка

Версия прошивки: **1.1.1**. Пользовательская инструкция и комплектующие —
в [корневом README](../README.md). Все команды ниже выполняются **из корня
клонированного репозитория**. Проверенная среда — macOS; автоматическая сборка
в GitHub Actions выполняется на Linux.

> Перед установкой проверьте [доступность Windy.app из вашей Wi-Fi-сети](../docs/API-CHECK.md).
> В некоторых сетях для полного прогноза нужен VPN на роутере.

## Проверенное оборудование и распиновка

- Waveshare **ESP32-S3-RGB-Matrix**, 32 МБ OPI Flash, 16 МБ OPI PSRAM.
- Одна **RGB-Matrix-P3-64×64**, HUB75, 1/32 scan.
- Питание панели 5 В отдельным силовым проводом; HUB75 передаёт данные.
- Драйвер **ESP32-HUB75-MatrixPanel-DMA 3.1.0**.
- Режим инициализации FM6126A, `clkphase=false`, тактирование 20 МГц.
- Два DMA-буфера во внутренней SRAM. Регулировка яркости через OE / `setBrightness8`.

| Сигналы | GPIO |
| --- | --- |
| R1 / G1 / B1 | 4 / 5 / 6 |
| R2 / G2 / B2 | 7 / 15 / 16 |
| A / B / C / D / E | 18 / 8 / 3 / 42 / 9 |
| LAT / OE / CLK | 40 / 2 / 41 |
| BOOT | 0 |

`FM6126A` — выбранный режим библиотеки, а не прочитанная маркировка микросхемы.
Для другой платы или панели необходимо проверить распиновку и параметры.
Использованы [примеры Waveshare](https://github.com/waveshareteam/ESP32-S3-RGB-Matrix/tree/main/example/arduino_v3.3.7)
и [HUB75 DMA](https://github.com/mrcodetastic/ESP32-HUB75-MatrixPanel-DMA).

## Подготовка инструментов

| Инструмент / библиотека | Версия |
| --- | --- |
| Arduino CLI | 1.6.0 |
| Arduino core ESP32 | 3.3.7 |
| HUB75 DMA | 3.1.0 |
| ArduinoJson | 7.4.3 |
| esptool | 4.8.1 |
| Node.js | 20 или новее |
| Python | 3.9 или новее |
| Компилятор для native-тестов | `clang++`, C++17 |

1. Установите [Arduino CLI 1.6.0](https://github.com/arduino/arduino-cli/releases/tag/v1.6.0)
   для своей системы и добавьте его в `PATH`. Можно вместо этого задать
   `ARDUINO_CLI=/путь/к/arduino-cli`. На macOS `clang++` устанавливается через
   Xcode Command Line Tools: `xcode-select --install`.
2. Установите Node.js и Python.
3. Установите зафиксированные пакеты:

```sh
sh firmware/setup.sh
npm --prefix wind64-prototype ci
python3 -m venv .tools/serial-venv
.tools/serial-venv/bin/python -m pip install esptool==4.8.1
```

Пакеты Arduino сохраняются внутри `.tools/`. Эта папка не публикуется и может
занимать несколько гигабайт. Машинные пути генерируются автоматически; менять
пути в исходниках не нужно. `firmware/arduino-cli.yaml` содержит публичный адрес
индекса плат, а локальная конфигурация создаётся в `.tools/arduino-cli.local.yaml`.

## Сборка и проверки

```sh
npm --prefix wind64-prototype test
node firmware/tests/parity.mjs
sh firmware/build-wind64.sh
```

Результат сборки — `firmware/build/wind64/wind64.ino.bin`.
Скрипт генерирует `assets.h` и `web_page.h` из палитры, шрифта и `web.html`.
Он убирает абсолютный путь рабочей папки из встроенных строк компилятора.
Флаги платы:

```text
esp32:esp32:esp32s3:FlashMode=opi,FlashSize=32M,PSRAM=opi,USBMode=hwcdc,CDCOnBoot=cdc,PartitionScheme=app5M_little24M_32MB
```

Дополнительная проверка мобильной страницы требует установленного Google Chrome:

```sh
node firmware/tests/web.mjs
```

Она работает с синтетическими ответами и не использует домашний пароль.
Подробности результатов — в [отчёте проверки](../docs/VERIFICATION.md).

## Запись прошивки по USB

Подключите отдельное питание к **POWER**, а компьютер — к **USB** платы.
Закройте serial monitor. Определите порт, например:

```sh
ls /dev/cu.usbmodem*    # macOS
ls /dev/ttyACM*        # Linux
```

В следующих командах замените значение `WIND64_PORT` своим портом.

### Первоначальная установка из релиза

Скачайте `wind64-1.1.1-firmware.zip` со страницы
[релизов](https://github.com/kirilldmt/espwind/releases/latest), распакуйте его
в каталог `wind64-1.1.1` и проверьте контрольные суммы:

```sh
cd wind64-1.1.1
shasum -a 256 -c SHA256SUMS
cd ..
```

Пути ниже предполагают, что распакованный каталог расположен в корне проекта:

```sh
WIND64_PORT=/dev/cu.usbmodemXXXX
.tools/serial-venv/bin/python -m esptool --chip esp32s3 \
  --port "$WIND64_PORT" --baud 921600 write_flash -z \
  0x0 wind64-1.1.1/bootloader.bin \
  0x8000 wind64-1.1.1/partitions.bin \
  0xe000 wind64-1.1.1/boot_app0.bin \
  0x10000 wind64-1.1.1/firmware.bin
```

Полный комплект предназначен для **указанной платы с 32 МБ Flash**. Он заменяет
загрузчик и разметку; перед первой установкой сохраните прежнюю flash, если
планируете к ней возвращаться. В релизе нет NVS с чужими Wi-Fi-настройками.

### Обновление уже установленного WIND64

Для этой же разметки достаточно записать одно приложение — NVS с Wi-Fi и
яркостью сохранится:

```sh
WIND64_PORT=/dev/cu.usbmodemXXXX
.tools/serial-venv/bin/python -m esptool --chip esp32s3 \
  --port "$WIND64_PORT" --baud 921600 write_flash -z \
  0x10000 firmware/build/wind64/wind64.ino.bin
```

Для готового релизного файла замените последний путь на `wind64-1.1.1/firmware.bin`.
Дождитесь `Hash of data verified` и перезапуска. Во время записи матрица не рисует.
На некоторых macOS-системах открытие USB CDC также перезапускает ESP32.
Если порт не определяется, удерживайте BOOT, нажмите и отпустите RESET, затем
отпустите BOOT. Удержание BOOT при сбросе и удержание на работающем табло — разные действия.

### Резервная копия и откат

До первой установки можно прочитать все 32 МБ flash:

```sh
WIND64_PORT=/dev/cu.usbmodemXXXX
mkdir -p device-backups
.tools/serial-venv/bin/python -m esptool --chip esp32s3 \
  --port "$WIND64_PORT" read_flash 0x0 0x2000000 device-backups/before-wind64.bin
```

Полная flash может содержать ваши пароли. Каталог `device-backups/` исключён
из Git; не прикладывайте такие копии к публичным issues или релизам.
Для отката приложения WIND64 запишите предыдущий релизный `firmware.bin`
по `0x10000`. Восстановление всей прежней flash заменит и настройки устройства.

## Устройство программы

| Файл | Назначение |
| --- | --- |
| `wind64/main.cpp` | Плата, FreeRTOS, Wi-Fi, HTTPS, NTP, веб-сервер, NVS |
| `wind64/core.*` | Календарь, выбор сессий, история, шрифт, частицы и отрисовка |
| `wind64/polling.*` | Монотонные сроки запросов, повторы, Retry-After |
| `wind64/weather_parser.*` | Проверка и нормализация погодных ответов |
| `wind64/web.html` | Встроенная страница настроек без CDN |
| `wind64/wind64.ino` | Точка входа Arduino |
| `scripts/` | Настройка инструментов и генерация ресурсов |
| `tests/` | Сопоставление с прототипом и проверки страницы настроек |

Погода и управление работают на другом ядре относительно отрисовки. Кадры,
история и JSON находятся в PSRAM. HTTP/TLS не выполняются в цикле кадра.
Рендер читает отдельный снимок состояния; расчёты и рисование не удерживают
общий mutex. Статичные прогнозные экраны повторно не записываются в DMA.
Частицы обновляются с целевой частотой 25 FPS; график пересчитывается раз в секунду.
Переход между экранами занимает 400 мс, развёртка DMA — около 250 Гц по данным драйвера.

## Данные и свежесть

Крон: `60.0111353, 29.6915455`, Windy.app spot `585111`, модель `gfs27_long`,
шаг `1h`. Загружаются восемь суток, включая сегодня: недельный экран показывает
сегодня + 6 дней, а лучший день выбирается среди семи дней начиная с завтра.
Скорость — `hypot(UGRD, VGRD)`; направление хранится FROM и рисуется как TO.

| Источник | Интервал | Предупреждение / устаревание |
| --- | --- | --- |
| Прогноз | 1 час и при смене московской даты | 6 часов после получения или 18 часов после запуска модели |
| KITEPITER, `1chipru_840d8eaa9b63` | 5 минут | 15 / 30 минут с измерения |
| PULKOVO, `ULLI` | 15 минут | 60 / 90 минут с измерения |

Номинально получается около 408 запросов в сутки. Есть положительное случайное
смещение до 30 секунд и минимальная пауза между запросами 2 секунды. Короткий
обрыв Wi-Fi не сбрасывает сроки. После ошибки пауза растёт: 1, 2, 4, 8… минут
до часа; HTTP 401/403/429 сразу дают не менее часа. `Retry-After` принимается в
секундах или как дата GMT. HTTP 429 и 503 с Retry-After приостанавливают весь хост.

Буфер ответа растёт от 32 до 768 КБ и используется повторно. JSON-фильтр оставляет
нужные поля. При ошибке остаются прежние данные с исходными временными метками.
Неизвестное значение не подменяется нулём или предыдущим известным значением.
История — до 1024 измерений на станцию, до 30 часов; график показывает 6 часов.
Разрывы больше 15/45 минут не соединяются. Время и расписание — UTC+3.
До синхронизации NTP действует ночной предел яркости. HTTPS проверяет сертификаты;
`setInsecure` не используется. Обновления по сети / OTA пока нет.

## Диагностика

Откройте **http://wind64.local/api/status** или IP устройства с `/api/status`.
`connected: true` означает только Wi-Fi; получение погоды проверяется отдельно.
Подробное руководство — [здесь](../docs/API-CHECK.md).

`polling` показывает попытки, успехи, подряд идущие ошибки, последний HTTP-код,
длительность, байты и время до следующей попытки. `apiCooldownMs` — общая пауза.
`frames` считает записи в DMA, `skippedFrames` — пропущенные повторные записи.
`slowFrames` — циклы длиннее 40 мс; `meanFrameUs` включает пропущенные циклы.
Ответ `/api/status` содержит временный токен страницы и имя Wi-Fi-сети:
перед публикацией диагностики удалите поля `token` и `ssid`.

USB-монитор, с указанием своего порта:

```sh
.tools/serial-venv/bin/python firmware/serialctl.py --port /dev/cu.usbmodemXXXX status --interactive
```

Команды: `status`, `setup`, `reconnect`, `quit`. Для нескольких команд держите
одну сессию открытой. Настройки хранятся в NVS, namespace `wind64`.
Новая сеть сохраняется только после успешного подключения; попытка длится 25 секунд.
POST `/api/settings` и `/api/wifi` требуют токена страницы и допустимого Origin.
Короткое нажатие BOOT в основной прошивке яркость не меняет.

## Собрать комплект релиза

После успешных проверок и сборки:

```sh
python3 firmware/scripts/package-release.py
```

В `firmware/build/dist/` появится ZIP с четырьмя бинарными файлами, инструкцией,
лицензиями, манифестом и SHA-256. Полные flash-копии и локальные отчёты устройства
в комплект не попадают. Исходники соответствующего коммита доступны отдельно
через стандартные архивы GitHub Release.
